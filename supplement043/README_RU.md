## Зачем ещё один короткий расчёт

Это дополнение к завершённому протоколу, а не исправление полученных метрик.

1. В матрице 042 отсутствует уже давно сохранённый per-tensor экспорт
   `export_per_tensor_recalibrated.json` с целочисленным порогом 22. Именно он
   нужен для прямого сравнения прежнего maxabs-экспорта после калибровки с
   процентильным вариантом на будущем периоде. Артефакт не переобучается.
2. Счётчики clipping в 042 относятся к значениям **до ReLU**. Отрицательные
   значения, которые ReLU затем обнуляет, нельзя представлять как эффективное
   насыщение скрытых активаций. Дополнение сохраняет прежние счётчики и добавляет
   отдельные счётчики после учёта ReLU.

Все прежние семь моделей оцениваются повторно только как контроль тождественности
расчёта. Метрики по строкам, векторам и ограниченным частотам, по дням и типам атак
сравниваются с 042. Изменение моделей, порогов или значимое изменение прежних
метрик не допускается. Новая восьмая модель фиксирована до запуска; выбора
параметров по будущему периоду нет. Подключение платы не требуется.

## Запуск в Windows

Сохраните ZIP в `E:\ids-update-lab`, затем:

```powershell
Set-Location E:\ids-update-lab
Expand-Archive -LiteralPath .\supplement043.zip -DestinationPath .
.\.venv039\Scripts\python.exe .\supplement043\run043.py --workspace E:\ids-update-lab
```

Ожидаемое время: ориентировочно 2–5 минут, исходя из 139 секунд предыдущего
расчёта; проверка хешей и скорость диска тоже влияют. Нужен сохранённый исходный
`runs\ids-completion-030\training\test_vectors.sqlite` с правильным SHA-256.
Если он отсутствует, запуск остановится до расчёта; автоматического сканирования
всего TON, переобучения и длительного восстановления нет.

Проверка результата:

```powershell
Get-Content .\runs\revision039-pc-043\STATUS043.json
```

Успешный итог: `status: complete`. Рядом с каталогом результатов автоматически
создаются `revision039-pc-043-results-*.zip` и файл контрольной суммы.
Передайте их для анализа. Они содержат новый результат, контрольные файлы 042,
код и журнал запуска. Исходные 040/041/042 не изменяются.

Выходной каталог должен быть новым. При повторном запуске существующий каталог
не удалять: используйте отдельный путь `--output` после разбора причины остановки.
Ключ `--inspect-only` выполняет предварительные проверки без расчёта.

## Что показывают результаты 042

Будущий период: 26–29 апреля 2019 года, **7 462 871 строка**, включая
401 231 нормальную и 7 061 640 атакующих; **3 782 505 уникальных векторов**.
Период ранее исследовался. Это оценка заранее фиксированных артефактов после
рецензирования, а не новый нетронутый тест. Приведены наблюдаемые проценты;
доверительных интервалов для этой таблицы в 042 нет.

| Вариант | Recall, % | FPR, % | Balanced accuracy, % | Изменение решений относительно B-I8, % |
|---|---:|---:|---:|---:|
| B-F32 | 43.801 | 2.151 | 70.825 | 2.679 |
| B-I8 | 44.428 | 2.190 | 71.119 | 0.000 |
| Совместимый maxabs, перенесённый порог | 47.208 | 28.810 | 59.199 | 6.004 |
| Per-channel, перенесённый порог | 47.117 | 28.777 | 59.170 | 5.878 |
| Per-channel, пересчитанный порог | 8.746 | 1.271 | 53.737 | 33.838 |
| Percentile 99.9, перенесённый порог | 42.781 | 1.676 | 70.553 | 3.238 |
| Percentile 99.9, пересчитанный порог | 43.096 | 1.764 | 70.666 | 3.246 |

Пересчитанный процентильный вариант меняет 242 223 решения относительно B-I8,
но только 66 353 относительно B-F32: соответственно 3.246% и 0.889%.
Близость к исходной float-модели и сохранение утверждённого int8-детектора —
разные требования. Пакет сохраняет выбранный конвейер, но сам по себе не повышает
качество IDS и не гарантирует арифметическую эквивалентность разных платформ.

Нельзя ограничиться метриками по строкам: у maxabs-экспорта FPR по строкам
28.810%, а при равном весе уникальных векторов 4.895%; у B-I8 — 2.190% и 4.015%.
Большой скачок по строкам связан с частыми шаблонами. При ограничении веса
одного вектора сотней строк FPR составляют 5.356% и 3.533% соответственно.
В статье сохранить все три способа взвешивания.

Общее качество неоднородно по атакам. Например, B-I8 имеет recall 99.936%
для backdoor и 5.104% для XSS. Процентильная модель с пересчитанным порогом
имеет 0% recall для ransomware. Близость общих метрик не доказывает одинаковое
поведение на всех типах атак. Дополнение 043 не предназначено для улучшения
этих результатов подбором параметров.

Поддерживаемого будущего окна с достаточным одновременным присутствием старых
атак A и добавленных в B атак не найдено. В новых сценариях будущие атаки не
представлены в обучении A/B. Это проверка временной чувствительности и смены
состава атак, а не доказательство сохранения качества на старых атаках.

|---|---:|---:|---:|

Во втором варианте формула верна в вещественной арифметике, но у C0083 старый

сохранять в статье безусловное утверждение о точной эквивалентности такого
экспорта в реализации. Нулевое наблюдаемое расхождение первого варианта тоже
не является доказательством для всех возможных входов. Замороженные модели
не исправляем задним числом.

## Что остаётся до ответа рецензентам

1. Короткое дополнение 043 закрывает прямой контроль maxabs/q22 и уточняет
   счётчики clipping. Оно не заменяет и не аннулирует завершённые 041/042.
2. После получения компонентов — сборка и проверка стенда, затем серия
   физических отключений питания. Программные перезапуски не заменяют её.
   Без осциллографа не заявлять доказанное попадание провала напряжения внутрь
   каждой краткой операции flash; отдельно подтверждать отключение питания
   и восстановление состояния.
3. Вторая плата ESP32-S3 отсутствует: явно сохранить ограничение одного
   экземпляра. ESP32-C3 не является повтором на втором экземпляре S3.
4. Внести результаты в рукопись и ответ по пунктам: сохранить численные
   расхождения 040, различать правильность установки и арифметическую
   эквивалентность, не объявлять все замечания закрытыми по одному `complete`.
