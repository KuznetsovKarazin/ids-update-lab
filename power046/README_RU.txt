Продолжение powercut-045 после попытки 61 — пакет 046
27 октября 2026 г. Автор оригинального программного обеспечения: Oleksandr Kuznetsov.

Назначение
Продолжить исходный план с попытки 62 по 200 после сохранённого таймаута
попытки 61 и отдельно подтверждённого позднего восстановления модели 749.
Пакет рассчитан только на проверенный комплект файлов данного инцидента.
Он не заменяет файлы revision040-kit и не перепрошивает платы.

Что установлено
В исходной серии выполнена 61 попытка. Подтверждены 58 отключений; 57 из них
сопровождались успешным восстановлением в исходном окне наблюдения.
Попытки 2, 40 и 48 не подтвердили отключения. Попытка 61 завершилась
no_response; этот результат остаётся в журнале и итоговой статистике.
Позднее STATUS вернул исходную модель B, версию 749, прежний SHA256,
слот 1 и selector_sequence 698. Независимо сверены все 12 контрольных
вычислений. Их максимальная абсолютная ошибка вероятности — 1,8767e-9
при допуске 2e-6. В приложенном позднем журнале только STATUS и INFER.

После отключения в попытке 61 журнал не содержит ни одной отправки
STATUS к ESP32 за примерно 20 секунд. Это указывает на затруднение
открытия/настройки COM13; точные ошибки этих открытий старая программа
не сохранила. Причина остаётся неустановленной. Сообщение Windows
NoMatchingEventsFound за выбранный интервал не доказывает отсутствие
всех возможных проблем управления питанием и не устанавливает причину.

Принцип продолжения
- Исходный план, порядок фаз, доли задержек и окно восстановления 20 с сохранены.
- Попытки 1–61 не повторяются; UPDATE версии 750 не отправляется повторно.
- Перед новой записью проверяются исходные файлы, поздняя диагностика,
  текущая идентичность модели и 12 контрольных вычислений.
- Допуск относится только к исходному таймауту попытки 61. Другие ошибки
  не получают автоматического разрешения.
- Оригинальный no_response сохраняется. Позднее восстановление учитывается отдельно.
- На время работы Windows получает временный запрос против автоматического сна.
  Постоянная схема питания не меняется. Закрытие крышки, ручной сон,
  выключение ПК и потеря питания этим запросом не предотвращаются.
- Для последующих открытий порта сохраняются подробные ошибки и список портов.
- Управление питанием, план задержек, прошивка и модели не заменяются.
Пакет не устраняет доказанную причину сбоя COM13: она пока не установлена.
Его назначение — проверяемое продолжение и подробная диагностика при повторении.

Подготовка
Сохраните ids-update-lab-power046-continuation.zip в E:\ids-update-lab.
В PowerShell:

Set-Location E:\ids-update-lab
Expand-Archive -LiteralPath .\ids-update-lab-power046-continuation.zip -DestinationPath .
$Py = 'E:\ids-update-lab\.venv039\Scripts\python.exe'
$Kit = 'E:\ids-update-lab\revision040-kit'
$Run = 'E:\ids-update-lab\runs\powercut-045'
$Pico = 'COM5'
$Mcu = 'COM13'
$Late = "$Run\diagnostic-controls61-1793094428982432400"

Платы оставьте в том же состоянии, в котором прошла поздняя проверка.
Не выполняйте flash, preflight, повторный probe или обычный resume старой программы.
Закройте другие программы последовательных портов. ПК должен получать питание;
не закрывайте крышку и не включайте сон вручную.

Команда продолжения
& $Py .\power046\run_powercut046.py run --root $Kit --plan "$Run\plan" --config "$Run\setup\powercut_config.json" --preflight "$Run\preflight" --mcu-port $Mcu --controller-port $Pico --board-id esp32s3-a0f262ebb558 --output "$Run\results" --allow-unconfirmed-phase-timing --resume --late-recovery $Late

Для проверки файлов без оборудования можно сначала выполнить ту же команду
с добавленным --prepare-only. Она не должна обращаться к платам или изменять
исходную папку эксперимента. При любой ошибке проверки не меняйте контрольные
суммы и не удаляйте журналы — сохраните сообщение для разбора.

В конце
Итоговые снимки имеют имя summary_<time_ns>.json в runs\powercut-045\results.
При успешном завершении attempted_trials должно быть 200. no_response: 1
останется исходным результатом попытки 61; это не новый сбой продолжения.
Число подтверждённых отключений следует брать из rail_off_confirmed.
phase_confirmed останется 0: независимая аналоговая привязка момента
падения питания к операции flash не выполнена.

Get-ChildItem "$Run\results\summary_*.json" | Sort-Object LastWriteTime | Select-Object -Last 1 | ForEach-Object { Get-Content $_.FullName -Raw }

После complete отключите вход TPS, затем при завершении всей работы USB Pico.
При новой ошибке оставьте питание как есть и сохраните вывод. Не повторяйте
продолжение и не сбрасывайте плату до разбора; одноразовый допуск намеренно
не служит универсальным способом обхода остановок.

Архивирование после завершения процесса
$Stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
& $Py .\power045\bench045.py pack --run $Run --output "E:\ids-update-lab\runs\powercut-045-after046-$Stamp.zip"

Проверки пакета
Аппаратных запусков в облаке не выполнялось. VALIDATION046.json содержит
результаты выполненных проверок на ПК с имитацией последовательных портов.
Тесты требуют исходного извлечённого архива инцидента и поздней диагностики;
их пути задаются переменными окружения, указанными в файле тестов.
Для PowerShell (до продолжения либо на отдельной копии исходного архива):
$env:POWER046_INCIDENT_RUN = '<папка исходного распакованного архива>\run'
$env:POWER046_LATE_RECOVERY = $Late
& $Py -m unittest discover -s .\power046\tests -v

В results\continuation046_sources сохраняются точные новые исходники,
чтобы итоговый архив bench045 pack включал код выполненного продолжения.

Документация Microsoft по временному запрету автоматического сна:
https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadexecutionstate
