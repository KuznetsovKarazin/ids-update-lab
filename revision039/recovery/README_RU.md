# Продолжение аппаратной серии: recovery040

Автор оригинального программного кода: Oleksandr Kuznetsov.

Новый комплект `revision040-kit` устанавливается рядом с `revision039-kit`.
Старые результаты `runs/revision039` не изменяются. Нужны прежняя среда
`.venv039`, ESP32-S3 и её рабочий USB-кабель. FNB58, Pico и ключ питания
в этой серии не используются.

## Запуск

После распаковки архива в `E:\ids-update-lab`:

```powershell
Set-Location E:\ids-update-lab
powershell -NoProfile -ExecutionPolicy Bypass -File .\revision040-kit\revision039\recovery\Start-Recovery040.ps1 -Mode Run -Port COM13 -BoardId esp32s3-a0f262ebb558
```

Для проверки файлов без обращения к плате замените `Run` на `Inspect`.
Не открывайте COM13 в других программах во время аппаратного запуска.
Оставьте компьютер включённым, без перехода в сон.

## Что выполняется

1. Проверяются хеши исходного завершённого блока Og, входной панели и
   неизменённых прошивок вычислительного блока. Проверяется новый комплект.
2. Исходная серия целиком сохраняется внутри нового каталога
   `runs/revision039-recovery040/source_evidence039`.
3. Завершённые 26 624 вычисления Og переносятся с явной записью происхождения.
   Несовпадения меток и численных результатов остаются в сводке.
4. Подготавливаются образы исправленной реализации обновления прошивки.
5. Выполняются короткие проверки LR для Og и O2: обычное и сжатое обновление,
   пакет, отрицательные контроли, перезагрузка и повтор версии. Эти пилоты
   не входят в основные оценки затрат.
6. Полная матрица затрат Og выполняется заново, затем идут вычисления O2
   и полная матрица затрат O2. Старые частичные затраты остаются пилотными.
7. Формируются анализ и новый архив результатов. Архив создаётся и при
   ошибке, если новый каталог уже был инициализирован.

Это продолжение USB-серии: энергия и физические отключения питания здесь
не измеряются. Завершение серии не означает полного численного совпадения
и не закрывает автоматически все замечания рецензентов.

Если запуск остановится, сохраните выведенный архив и пришлите его вместе
с последними строками консоли. Не удаляйте неуспешный шаг: повтор поверх
такого шага намеренно блокируется. Завершённые шаги при повторном запуске
проверяются по хешам и повторно не выполняются.
