# Эксперименты по рецензиям — пакет 039

Автор оригинального кода: Oleksandr Kuznetsov.

Архив распаковывается в отдельную папку `revision039-kit`. Старые результаты,
код и архивы в `E:\ids-update-lab` остаются на месте. Рукопись не изменяется.

## 1. Распаковать и проверить исходные данные

Сохраните `ids-update-lab-revision039.zip` в `E:\ids-update-lab`.

```powershell
Set-Location E:\ids-update-lab
Expand-Archive -LiteralPath .\ids-update-lab-revision039.zip -DestinationPath .
powershell -NoProfile -ExecutionPolicy Bypass -File .\revision039-kit\revision039\Start-Revision039.ps1 -Mode Inspect
```

Создаётся отдельная `.venv039`, устанавливаются зависимости. Проверка ищет
исходную серию030, сохранённые выборки и 23 сетевых CSV TON_IoT. Если локальная
серия030 не найдена, используются опубликованные замороженные модели из пакета;
проверочные выборки восстанавливаются из исходных CSV. Плата не
прошивается и порт не открывается. Нормально, если второй платы пока нет.

Если CSV хранятся на другом диске, добавьте к последующим командам:

```powershell
-DataRoot 'D:\TON_IoT_network'
```

Если исходная серия030 была перемещена, добавьте:

```powershell
-PriorRun 'E:\путь\ids-completion-030'
```

Путь должен вести к исходному запуску с `training\models`, а не к архиву ZIP.
Не переименовывайте и не подменяйте недостающие файлы другими выборками.

## 2. Запустить имеющуюся ESP32-S3

Подключите плату обычным рабочим USB-кабелем. Закройте serial monitor и программы,
занимающие её COM-порт. Для этой серии FNB58 не требуется; не начинайте запись
энергии. Компьютер должен оставаться включённым без сна.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\revision039-kit\revision039\Start-Revision039.ps1 -Mode MCU -Port COM13 -BoardId esp32s3-a0f262ebb558
```

Команда сначала готовит подписанные артефакты и эталонные ответы. Затем сама
проверяет MAC/тип платы перед прошивкой, выполняет расширенную проверку численных
результатов и сравнивает package / full image / compressed full image в сборках
Og и O2. После серии автоматически создаются таблицы затрат и парные
доверительные интервалы в `runs\revision039\analysis`. Во время этой серии лабораторная прошивка и состояние обновления на
ESP32 заменяются. Старые результаты на диске не меняются.

Это продолжительный автоматический запуск. Не отключайте USB и не запускайте
одновременно тяжёлые расчёты или другую программу работы с платой. Если возникнет
ошибка, серия остановится и сохранит журнал; не стирайте flash вручную в попытке
продолжить. Сначала разберите причину по архиву и логам.

## 3. Выполнить расчёты на ПК

После аппаратной серии запустите:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\revision039-kit\revision039\Start-Revision039.ps1 -Mode PC
```

Будут выбраны хронологические сценарии по покрытию данных, выполнено обучение
фиксированных моделей, проверена устойчивость порогов и оценены уже сохранённые
percentile-варианты на будущем трафике. Нужны исходные 23 CSV; ожидаются длительные
чтение данных и расчёты. Скорость зависит от диска и процессора.

Можно выполнить обе части последовательно одной командой вместо шагов 2–3:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\revision039-kit\revision039\Start-Revision039.ps1 -Mode All -Port COM13 -BoardId esp32s3-a0f262ebb558
```

`All` выполняет подготовку, расчёты на ПК, затем MCU. Для начала работы с готовой
платой удобнее отдельный `MCU`. Успешные этапы проверяются по хешам и повторно
не выполняются. Неуспешные измерения автоматически не перезапускаются.

## 4. Вторая плата и отключения питания

Вторую ESP32-S3 запускают тем же `-Mode MCU`, но с её COM-портом и MAC в `-BoardId`.
Идентификатор первой платы второй присваивать нельзя. Её результаты попадут в
отдельную подпапку той же кампании. Если MAC ещё неизвестен:

```powershell
.\.venv039\Scripts\python.exe -m esptool --chip esp32s3 --port COM13 flash_id
```

Команда читает идентификатор и перезапускает плату, но не прошивает её.

Физические отключения **не входят** в `MCU` или `All`. Pico 2 будет контроллером,
но для коммутации ESP32 нужен внешний ключ питания и проверенная схема контроля
напряжения. Читайте `revision039\powercut\README.md` и пример конфигурации.
Без выполненной аппаратной проверки этот этап остаётся незавершённым; сброс
прошивки не засчитывается как отключение питания.

## 5. Что прислать для анализа

Результаты по умолчанию находятся в `E:\ids-update-lab\runs\revision039`.
После каждого запуска рядом создаётся новый архив `revision039-results-*.zip`.
Последний архив содержит все накопленные результаты новой кампании, в том числе
сообщения об ошибках, если они были.

```powershell
Get-Content .\runs\revision039\STATUS039.json
Get-ChildItem .\runs\revision039-results-*.zip | Sort-Object LastWriteTime -Descending | Select-Object -First 1
```

Пришлите `STATUS039.json` и последний архив. Для ручной упаковки после дополнительных
этапов используйте `Start-Revision039.ps1 -Mode Pack`.

Итоговый архив предназначен для анализа: он может содержать выборки, полученные из
датасета. Это не команда публикации на GitHub/Zenodo. Старые опубликованные архивы
и результаты не заменяются.
