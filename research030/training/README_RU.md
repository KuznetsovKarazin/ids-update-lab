# Обучение и оценка 030

Это автономная часть общего запуска. Она не обращается к MCU и не записывает энергию. Основная команда общего комплекта вызывает её автоматически.

При отдельном запуске из корня проекта:

```powershell
.\.venv\Scripts\python.exe .\research030\training\run_training030.py --root E:\ids-update-lab --output runs\research030-training
```

Если CSV расположены вне проекта, добавьте `--data-root D:\папка_с_23_CSV`. Выходная папка должна быть новой. Входные файлы сверяются по SHA-256 с теми, на которых выполнена диагностика 028.

## Что зафиксировано

Границы временных ролей взяты из `protocol/coverage_selection.json`. Выбор сделан по покрытию, до нового обучения. Данные уже исследовались в 023/028: это серия после разведочного анализа, а не впервые открытый независимый тест.

У внутренних границ исключаются 60 секунд с каждой стороны. Поток должен полностью завершиться внутри своей роли: `ts + duration < конец`. Для времени и длительности используются исходные числа двойной точности; модель получает восемь канонических float32-признаков. Это проверка временной принадлежности потока; независимость сессий не установлена.

Сначала сканируются все 23 файла. После исключений в каждой атомарной роли должно остаться не менее 1000 нормальных и 1000 атакующих строк. При нарушении программа завершается до обучения: правила автоматически не ослабляются.

В A и B обучаются все четыре зафиксированных варианта:

1. LR после log1p и стандартизации, C=1.
2. Дерево на исходных признаках, глубина не более 5, минимум 50 выборочных строк в листе.
3. MLP 8→16→8→1 с двумя ReLU, 30 эпох Adam и одинаковой инициализацией для A/B.
4. Целочисленный экспорт той же MLP: int8-веса и активации, int32-накопление, int64-произведение при целочисленном пересчёте масштаба.

MLP является собственной небольшой реализацией, а не TFLite Micro. Время и результаты нельзя приписывать библиотеке TFLite.

Порог выбирается только по нормальным записям соответствующей калибровки: наиболее разрешающий порог с эмпирическим FPR не выше 1%. Равные оценки не разделяются. У float-моделей решение определяется строгим `p > threshold`; порог 1 означает постоянное решение «норма». У int8 решение `q >= q_threshold`, значение 128 означает постоянное решение «норма». Гарантии FPR на будущем трафике нет. Низкий recall и плохой внешний результат сохраняются без изменения правил.

Выборки обучения ограничены: до 100000 нормальных записей и до 50000 записей каждого типа атаки. Выбор по минимальным детерминированным хеш-приоритетам номера исходной строки; значения признаков и результаты модели на него не влияют. Вес компенсирует выборку внутри типа, затем уравновешивает два класса. Эти же веса применяются при оценивании масштаба LR/MLP. Популяции обучения A и B вложены, но ограниченные выборки не обязаны быть вложенными. Калибровка содержит до 100000 строк на пару «метка, тип»; для выбранных окон все нормальные записи помещаются без усечения.

## Что будет в результатах

`protocol_lock_before_data_and_predictions.json` фиксирует параметры, границы, код и среду до прогнозов. `sources.json`, `sampling.json` и `temporal_support_after_purge.json` показывают происхождение данных, выборочные ID и исключения.

`evaluation.json` содержит FPR, recall, balanced accuracy, расхождения решений и парные изменения относительно согласованной B. Представлены веса по строкам, равный суммарный вес каждого вектора и ограничение частоты 100. При противоречивых метках обе метки сохраняются в исходных пропорциях. Отдельно показаны топ-20 частых векторов, остальные входы, известные/новые векторы обучения и группы типов атак. Частота вектора для весов определяется по всему общему тесту, включая его нормальные и атакующие записи.

`by_day.json` и `by_attack_type.json` дают разбиение. При числе тестовых дней меньше восьми bootstrap-интервалы не рассчитываются; `uncertainty.json` содержит описательное исключение одного дня за раз. Десятки тысяч повторяющихся строк не объявляются независимыми испытаниями. Если дней не менее восьми, интервалы — условный парный bootstrap по дням с явно указанной предпосылкой их обменности.

В `models` находятся A/B и сценарии устаревших компонентов. Они являются контролируемыми ошибками развёртывания, а не описанием всех существующих OTA-средств. Совместимый LR сохраняет вероятности или решения в точной арифметике; фактическая float32-погрешность измеряется. Для int8 совместимый пересчёт первого слоя и повторная квантизация проверяются без обещания точного совпадения. Старый целочисленный код порога и старый смысловой порог представлены раздельно.

`hardware_vectors` содержит первые 258 уникальных тестовых векторов в фиксированном байтовом порядке и эталонные ответы каждого варианта. Они выбраны до прогнозов и проверяют перенос, а не оценивают качество вместо полного теста. `test_vectors.sqlite` сохраняет достаточную статистику для повторного анализа; `samples/*.npz` — использованные выборки обучения и калибровки. Эти файлы остаются локально и входят в полное локальное резервное копирование.

## Проверка комплекта

В `validation` записаны проверки программного обеспечения. Прогон первого файла TON проверяет сканирование, временные правила и выборку; моделей он не обучал. Синтетический прогон проверяет все этапы обучения, экспорта и оценки. Ни один из этих прогонов не является новым научным результатом на полном TON или на MCU.

Требуются Python 3.11/3.13, NumPy и scikit-learn. Версии зависимостей записываются в фиксации протокола. Побитовая идентичность обучения между разными версиями библиотек и архитектурами не утверждается; опубликованные модельные JSON, хеши и эталонные входы определяют конкретный воспроизводимый экземпляр.
