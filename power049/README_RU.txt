Установка и запуск
Распакуйте ZIP в E:\ids-update-lab. Появится отдельная папка power049.
Сохраните текущее питание и подключения до проверки.
Из текущего PowerShell в E:\ids-update-lab выполните один раз:

& $Py .\power049\run_powercut049.py run --root $Kit --plan "$Run\plan" --config "$Run\setup\powercut_config.json" --preflight "$Run\preflight" --mcu-port COM13 --controller-port COM5 --board-id esp32s3-a0f262ebb558 --output "$Run\results" --allow-unconfirmed-phase-timing --resume --verify-incident186

Ожидаемые существующие переменные:
$Py  = 'E:\ids-update-lab\.venv039\Scripts\python.exe'
$Kit = 'E:\ids-update-lab\revision040-kit'
$Run = 'E:\ids-update-lab\runs\powercut-045'

Проверка до обновления
1. Проверяются хеши 372 файлов прежнего Run, конфигурация, план, preflight,
   исходник runner039 и отсутствие более поздних попыток.
2. COM13 открывается один раз с DTR=False/RTS=False. Выполняется только
   STATUS → 12 контрольных INFER для модели A → STATUS.
   Требуется точная старая модель A/1696, slot 0, selector 1543,
   прежние SHA256, build, schema, ABI и остальные поля идентичности.
3. Сырые/разобранные ответы, снимки COM13 и результат проверки сохраняются
   отдельно в results\incident186_late049 до первого нового обновления.
   При ошибке сохраняются также уже полученные частичные данные.
4. Только после успешной проверки MCU открывается Pico. Требуются ID с прежней
   конфигурацией и armed=True, enabled=True, а ADC должен дать 3,0–3,6 В.
   ARM/ON/reset для исправления состояния не отправляются.
5. Сохраняется отдельный допуск continuation049_admission.json. Дополнительный
   STATUS перед обновлением снова должен совпасть с A/1696.

Если COM13 недоступен, модель другая (включая B/1698), контроль не совпал,
Pico не armed или измерение питания не прошло — обновления не начинаются.
Попытка 186 в исходном журнале остаётся no_response даже при позднем old_valid.

Продолжение
Осталось 14 попыток, с 187 по 200. Подготовительные версии: 1699/1700;
первый кандидат: 1701. Подписанные версии и старые попытки не повторяются.
Сохраняются план, задержки, выключение на 2 секунды и исходный алгоритм
восстановления с номинальным окном 20 секунд. Как и ранее, блокирующие вызовы
ОС/serial могут завершаться за его пределами; правило принятия ответа прежнее.
ADC читается после решения об успешном STATUS или после истечения окна.
При новом неуспехе QueryDosDevice(COM13) вызывается после ADC, перед перечнем
портов, также вне исходного окна. Ошибка ADC не меняет принятое решение STATUS.
При завершении дополнительный ON не отправляется.

При новом сбое остановка сохраняется для исследования. Не повторяйте команду
и не удаляйте continuation049_attempt.json/continuation049_admission.json.
Достижение 200 означает завершение плана попыток, а не 200 успешных восстановлений:
все три исторических no_response остаются в итоговой статистике.
Отдельный контроль047 на 100 циклов не входит в основной знаменатель.
