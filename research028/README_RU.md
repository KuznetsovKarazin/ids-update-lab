# Этап 028: полная диагностика TON перед переобучением

Запуск выполняется **на ПК, без доступа к COM13 и без перепрошивки**. Можно оставить текущий опыт с платой работающим. Никакая модель не обучается и пороги не меняются.

## Что проверяем

1. Все 23 исходных файла TON, включая строки, совпадающие по восьми float32-признакам со старым CSV. Отдельно: весь валидный набор, известные векторы и остальные.
2. Все десять замороженных вариантов: LR A/B, устаревшие компоненты, совместимые экспорты и DT A/B.
3. Три способа взвешивания: каждая строка; равный суммарный вес каждого вектора; ограничение суммарного веса вектора величиной 100. Противоречивые метки сохраняются: вектор с 1 нормальной и 3 атакующими строками при равном весе даёт массу 0.25 нормальному классу и 0.75 атакующему. Это разные оцениваемые величины, а не способ объявить строки независимыми.
4. Топ-20 векторов по частоте и остальная выборка; отдельно топ-20 изменившихся решений DT A→B. Для них — совместные распределения `proto`, `conn_state`, `service`, `label`, `type`, а также `history`, если такой столбец существует. Отсутствующий столбец явно помечается. Одних счётчиков пакетов недостаточно, чтобы утверждать, что это SYN.
5. Полностью нулевой вектор, конфликты меток, вклад частых шаблонов, доли нулей по каждому признаку и классу.
6. Почасовая таблица покрытия и несколько заранее заданных хронологических окон A-fit → A-cal → дополнительная история B → B-cal → общий последующий тест. Показываются в том числе пустые группы. Код **не выбирает** границы и не сравнивает качество кандидатов. Перед обучением понадобятся выбор по покрытию, окончательная фиксация протокола и проверка разделения сеансов.

Это описание после разведочного анализа уже просмотренной коллекции, а не новый нетронутый независимый тест. Интервалы неопределённости здесь не рассчитываются: независимость строк/уникальных векторов/сеансов не установлена.

## Выполнение в PowerShell

Из `E:\ids-update-lab` распаковать архив в текущую папку. Должна появиться `research028`.

```powershell
Set-Location E:\ids-update-lab
.\.venv\Scripts\python.exe .\research028\tools\diagnose_ton028.py inspect --root E:\ids-update-lab
```

`inspect` проверит целостность комплекта и найдёт единственную папку с 23 файлами `Network_dataset_1.csv` ... `Network_dataset_23.csv`. Само содержимое CSV будет проверено по SHA-256 перед основным запуском.

Если вы получили `status: ready`, запустить:

```powershell
.\.venv\Scripts\python.exe .\research028\tools\diagnose_ton028.py run --root E:\ids-update-lab --output runs\ton-diagnostics-028
```

Если CSV находятся за пределами проекта или найдены две копии, явно укажите папку с самими CSV, например:

```powershell
.\.venv\Scripts\python.exe .\research028\tools\diagnose_ton028.py inspect --data-root "D:\datasets\TON"
.\.venv\Scripts\python.exe .\research028\tools\diagnose_ton028.py run --data-root "D:\datasets\TON" --output runs\ton-diagnostics-028
```

В этом примере `D:\datasets\TON` нужно заменить фактической папкой. Нельзя указывать ZIP вместо распакованных CSV. Требуются NumPy и cryptography, уже использовавшиеся в предыдущих этапах. Исходные CSV не изменяются.

## Время, диск, прерывание

Проходов по данным несколько: проверка SHA, агрегация, уточнение метаданных частых векторов, повторная проверка SHA. Время зависит от диска и ПК; программа сообщает этап и число строк примерно каждые 15 секунд. Полная коллекция содержит около 22.3 млн строк и занимает 3.37 ГБ. Для SQLite и транзакций желательно иметь **не менее 8 ГБ свободного места**; пик зависит от числа уникальных векторов. Память ограничивается порциями данных и дисковым SQLite.

Папка результата должна быть новой. При техническом прерывании повторить **ту же** команду с `--resume`:

```powershell
.\.venv\Scripts\python.exe .\research028\tools\diagnose_ton028.py run --root E:\ids-update-lab --output runs\ton-diagnostics-028 --resume
```

Завершённые файлы не учитываются повторно; незавершённая транзакция одного файла откатывается. Этап вычисления метрик уникальных векторов при прерывании начинается заново. SHA файлов, версия комплекта, версии Python/NumPy и параметры должны совпасть с исходным протоколом. Завершённый результат не перезаписывается. Не запускайте одновременно два процесса в одну папку результата.

## Что прислать

```powershell
Get-Content .\runs\ton-diagnostics-028\summary.json
.\.venv\Scripts\python.exe .\research028\tools\pack_results028.py --run runs\ton-diagnostics-028 --output ton-diagnostics-028-results.zip
```

Прислать `ton-diagnostics-028-results.zip`. Упаковщик проверяет завершение и контрольные суммы, включает отчёты, протокол, таблицы покрытия и журнал. Большой `vectors.sqlite3` — воспроизводимый промежуточный кэш; он остаётся у вас, его SHA записан. Самостоятельно удалять его до разбора результатов не требуется.

`--smoke-one-file` используется только для проверки комплекта на одном фиксированном исходном файле. Такие результаты явно обозначаются `single_file_smoke` и не заменяют полный запуск.

## Что будет следующим после результата

По таблице покрытия выбрать и зафиксировать один основной временной сценарий, не используя качество моделей для выбора. LR — контроль совместимого экспорта, дерево — второй уже поддерживаемый MCU-вариант. Для маленькой MLP и int8 нужны обучение/экспорт, отдельный численный эталон и поддержка в MCU; данный архив не выдаёт их за выполненную работу. Границы обучающих/калибровочных/тестовых интервалов и распределение типов атак необходимо согласовать с реальным покрытием, включая нулевые группы.
