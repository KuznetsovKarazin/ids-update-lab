# Проверка стека ESP32-S3, completion020

Те же исходники и команды Xtensa GCC дополнительно скомпилированы с
`-fstack-usage` в отдельные объектные файлы. Прошивки этим не изменены.

Размеры для 32-битного Xtensa: Model 2300 байт, Engine 4696 байт,
LineReader 8308 байт; максимальная строка 8224, envelope 4096 байт.

Самая глубокая явно проверенная цепочка обновления дерева:
app_main 14000 → Protocol::process 6496 → Engine::update 2512 →
Engine::install 10576 → Engine::validate 2368 → decode_tree_body 3232 байта.
Сумма кадров — **39184 байта**. Размер главного стека — **65536 байт**;
до дополнительных библиотечных вызовов остаётся 26352 байта.
В app_main уже учтены Engine, LineReader и другие постоянные локальные объекты:
прибавлять их повторно к сумме не нужно.

Дополнительно скомпилированы stack usage для шести модулей mbedTLS.
Используемые RSA PKCS#1 v1.5 verify wrapper/public frames имеют десятки байт;
крупные временные буферы RSA размещаются отдельно. Проверка подписи и разбор
дерева выполняются последовательно, поэтому их наиболее глубокие вызовы не
складываются друг с другом.

Конкретного основания ожидать переполнение в этой цепочке при 64 КиБ нет.
Прежние 16 КиБ были бы недостаточны. Это статическая проверка структуры кадров,
не доказанный максимум полного стека FreeRTOS и не измерение peak RAM всей
системы: библиотечные, системные кадры и динамическая куча требуют отдельного
учёта. Не следует публиковать 39184 или 65536 байт как измеренный пик RAM.

Сырые `.su`, команды дополнительной компиляции и sizeof-probe находятся здесь.
Настройки главного стека должны быть одинаковыми во всех сравниваемых прошивках.
