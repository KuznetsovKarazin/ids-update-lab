# Отдельный короткий опыт: две ротации журнала

Основные серии перед каждым испытанием заново подготавливают память. Поэтому
они проверяют контролируемое исходное состояние, но не достигают заполнения
страниц журнала. Этот отдельный опыт выполняет 70 последовательных успешных
обновлений без прерываний. Он не требует второго MCU или переключателя питания.

Начальное условие: на ESP32 установлена новая прошивка **completion020 LR/bundle**.
Сначала выполняется обычная команда `flash` для LR/bundle из основной инструкции.
Скрипт проверяет текущий STATUS и ROM MAC, сохраняет исходное состояние, затем
сам явно перепрошивает заводскую A и очищает модельные области и журнал.
Эта подготовка сбрасывает программную историю версий; её время не включается
в время обновления.

```powershell
Set-Location E:\ids-update-lab
.\.venv\Scripts\python.exe .\completion020\tools\check_journal_rotation.py --port COM13 --board-id esp32s3-a0f262ebb558 --output runs\esp32-journal-rotation-020 --timeout 20
Get-Content .\runs\esp32-journal-rotation-020\summary.json
```

Используются первые 70 существующих подписанных пакетов из каталога powercut.
Название каталога историческое: **данный скрипт не отключает питание и не вводит
отказы**. Все 70 пакетов содержат одни и те же замороженные параметры B;
различаются версия и подписанная идентичность.

Ожидается:

- `status: complete`;
- 70 принятых обновлений;
- 74 контрольных вычисления, 0 несовпадений меток;
- 3 проверенные программные перезагрузки — после обновлений 32, 64 и 70;
- `final_selector_sequence: 71`, `final_version: 10070`, `final_active_slot: 0`.

Изначально журнал содержит запись 1. Обновление 32 создаёт запись 33 на другой
странице; обновление 64 создаёт запись 65 после стирания ранее занятой первой
страницы. Скрипт проверяет последовательность, слоты, подписанный пакет и
контрольный ответ после каждого обновления. Само исполнение инструкции стирания
не измеряется внешним прибором: переход страниц следует из фиксированного кода
и проверенного номера последовательности. В native-проверке дополнительно
читаются обе страницы и проверяются записи 33, 64, 65 и 71.

Это **один функциональный опыт**, а не 70 независимых повторов для статистики
надёжности. Физических отключений нет. После успешного завершения запускается
основная серия: она сама подготавливает своё исходное состояние. Если опыт
завершился ошибкой, сохраните весь каталог и не запускайте его снова вслепую.

Native-проверка runner: `python -m unittest discover -s tests -p test_journal_rotation.py -v`.
Она запускает настоящее C++-ядро с RSA-проверкой и не выдаёт вычисления на ПК
за измерения MCU. Итог сохранён в `validation/rotation/native_rotation_summary.json`.
