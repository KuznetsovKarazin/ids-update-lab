# Этап 025: сколько стоит стирать только необходимую область flash

В этом комплекте — четыре готовые прошивки ESP32-S3 и автоматический запуск эксперимента. Логистическая регрессия (LR) и дерево решений (DT) используют прежние подписанные модели A/B/C из completion020. Меняется способ стирания неактивного слота перед установкой: все 64 КиБ либо необходимое число секторов по 4 КиБ.

Для нынешних пакетов достаточно 4 КиБ. Вместимость каждого слота остаётся 64 КиБ; расчёт учитывает и 8 байт заголовка. Проверяем, как это влияет на время установки на плате. Уменьшение запрашиваемой области в 16 раз не означает заранее такого же ускорения.

Каждая цепочка автоматически начинается с прошивки заводской A и очистки лабораторного состояния моделей/журнала. Затем B записывается в чистый слот, C — поверх ранее принятой A, и проверяется перезагрузка. Параметры C совпадают с B; версия и имя релиза другие. Результаты прежних этапов не используются как новые повторы.

## 1. Распаковать и проверить комплект

Сохраните `ids-update-lab-erase-025.zip` в `E:\ids-update-lab`. Откройте PowerShell:

```powershell
Set-Location E:\ids-update-lab
Expand-Archive -LiteralPath .\ids-update-lab-erase-025.zip -DestinationPath .
Get-PnpDevice -PresentOnly | Where-Object { $_.FriendlyName -match '\(COM\d+\)' } | Select-Object Status, FriendlyName
```

Все команды ниже выполняются из `E:\ids-update-lab`. Используем прежнее виртуальное окружение; устанавливать ESP-IDF или собирать прошивки на Windows не нужно.

Проверка файлов, подписей моделей, эталонных вычислений и привязки моделей к прошивкам:

```powershell
.\.venv\Scripts\python.exe .\stage025\tools\run_erase025.py inspect
```

Ожидается JSON с `"status": "complete"`, четырьмя конфигурациями и `"hardware_access_attempted": false`. Эта команда не обращается к плате. Если появляется ошибка, сохраните её текст и не переходите к прошивке. Если папка `stage025` уже существует, не смешивайте комплекты распаковкой с `-Force`.

## 2. Подготовить соединение

Используется ESP32-S3 с идентификатором `esp32s3-a0f262ebb558`, ранее доступная на COM13. Если номер изменился, замените `COM13` во всех командах. COM измерителя FNB58 не подходит.

Закройте последовательный монитор, терминал платы и другие программы, занимающие её COM-порт. Сохраните одну схему питания и подключения на весь пилот и серию. Если плата уже подключена через FNB58, можно оставить это соединение. В этом этапе энергия не измеряется, запись графика FNB58 не требуется.

Скрипт сначала читает STATUS текущей прошивки 020/025, затем перед каждой записью проверяет тип чипа и MAC через ROM-загрузчик. Он самостоятельно меняет четыре прошивки и очищает область моделей/журнала `0x3b0000..0x3d1fff`. Это сбрасывает установленную модель и программную историю версий для лабораторной цепочки. Ручные `erase_region` и `write_flash` между опытами не нужны.

## 3. Выполнить пилот

```powershell
.\.venv\Scripts\python.exe .\stage025\tools\run_erase025.py pilot --port COM13 --board-id esp32s3-a0f262ebb558 --output runs\esp32-erase-025-pilot --timeout 20
Get-Content .\runs\esp32-erase-025-pilot\summary.json
```

Пилот включает 28 цепочек: четыре полных проверки моделей A/B/C и 24 проверки программного прерывания обновления при повторном использовании слота. Во время работы будут строки `pilot 1/28`, …, `pilot 28/28` и счётчики вычислений. При автоматических перезагрузках не нажимайте кнопки платы.

Успешный итог:

| Поле summary.json | Значение |
|---|---:|
| status | complete |
| completed_trials | 28 |
| inferred_records | 3316 |
| label_mismatches | 0 |
| faults_verified | 24 |
| negative_controls_passed | 32 |

Это проверка регрессий после изменения хранения. Программная перезагрузка между операциями flash не является физическим отключением питания.

## 4. Выполнить основную серию

После успешного пилота можно сразу выполнить:

```powershell
.\.venv\Scripts\python.exe .\stage025\tools\run_erase025.py series --port COM13 --board-id esp32s3-a0f262ebb558 --pilot-run runs\esp32-erase-025-pilot --output runs\esp32-erase-025-series --timeout 20
Get-Content .\runs\esp32-erase-025-series\summary.json
```

Скрипт проверяет, что пилот завершён на этой плате и с этим комплектом. План фиксирован заранее: 30 блоков × четыре конфигурации = 120 цепочек, по два измеряемых обновления в каждой. Порядок конфигураций чередуется; для каждого попарного сравнения порядок одинаково часто прямой и обратный. Число повторов не меняется после просмотра результатов.

Ожидается `status: complete`, `completed_trials: 120`, `accepted_updates: 240`, `inferred_records: 5880`, `label_mismatches: 0`. Скрипт останавливается при первой ошибке и сохраняет уже полученные данные. Частичная серия не выдаётся за полную.

В измеряемое время входит работа установки на самом MCU. Время перепрошивки/подготовки очередной цепочки исключено. Исходные интервалы обмена с Windows сохраняются отдельно. Не отключайте USB и не меняйте питание между блоками.

## 5. Получить сводку и отправить результаты

После полной серии:

```powershell
.\.venv\Scripts\python.exe .\stage025\tools\summarize_erase025.py --run runs\esp32-erase-025-series --output runs\esp32-erase-025-analysis
Compress-Archive -Path .\runs\esp32-erase-025-pilot, .\runs\esp32-erase-025-series, .\runs\esp32-erase-025-analysis, .\stage025\KIT_MANIFEST.json, .\stage025\BUILD_METADATA.json, .\stage025\protocol.json -DestinationPath .\esp32-erase-025-results.zip
```

Пришлите `esp32-erase-025-results.zip`. В сводке будут медианы, 5-й и 95-й процентили по каждой группе и парные разности времени с 95% bootstrap-интервалами. Основной результат — разность «необходимые секторы минус полный слот» для B→C, отдельно для LR и DT. Отрицательная разность означает меньшее время установки.

Не добавляйте файлы и заметки внутрь завершённых папок пилота/серии: их содержимое связано контрольными суммами. Сводка специально создаётся в отдельной папке. Не удаляйте неудачные прогоны и не выбирайте для статьи только быстрые измерения.

## Если что-то остановилось

Не перепрошивайте плату вручную и не стирайте результаты. Сохраните текст ошибки и `summary.json` той команды, которая остановилась. Для ошибки пилота:

```powershell
Get-Content .\runs\esp32-erase-025-pilot\summary.json
Compress-Archive -Path .\runs\esp32-erase-025-pilot -DestinationPath .\esp32-erase-025-pilot-failed.zip
```

Для ошибки основной серии используйте соответствующую папку `esp32-erase-025-series`. Если ошибка возникла до создания выходной папки, достаточно полного текста ошибки. Каталоги результатов должны быть новыми: сообщение о существующем каталоге не означает неисправность MCU. Возобновление с середины и автоматическое повторение записей отключены; причину сбоя разбираем по сохранённым журналам.

## Что этот этап добавляет статье

Получаем контролируемое сравнение двух способов стирания при тех же моделях, вместимости слотов, подписях и журнале выбора. Сопоставляем политики внутри одинакового перехода; разницу A→B и B→C нельзя целиком приписать чистоте flash, поскольку одновременно отличаются версия, слот и порядок операции.

Этап не переобучает модели и не пересчитывает качество IDS на тестовых данных. Он не измеряет энергию, срок службы flash или устойчивость к физическому отключению питания. Счётчики flash обозначают байты запросов к API, которые вернули успех; это не счётчики внутренних операций чипа. Проверки хранения на ПК и сведения о сборке включены в комплект и явно отделены от будущих результатов платы.

Подробные условия и правила анализа: `docs/EXPERIMENT_PROTOCOL_RU.md` и `protocol.json`. Исходники включены; файлы `tools/run_completion.py`, `tools/campaign_support.py` и `tools/legacy_runner018.py` сохранены как вспомогательные модули прежнего этапа. Для этого комплекта запускайте только команды 025 выше.
